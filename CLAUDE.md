# Коммиты

**Коммиты делает только человек.** Никогда не запускай `git commit`, `git add`,
`git push`, `git merge`, `git rebase` и прочие команды, меняющие историю или
индекс, — даже если задача выглядит законченной и даже если попросили
«закоммитить». Максимум — предложить готовое сообщение коммита текстом.
Читающие команды (`git status`, `git diff`, `git log`) использовать можно.

Правила ниже — для сообщений, которые ты предлагаешь, а не пишешь сам.

Сообщения коммитов — по Conventional Commits: `<type>(<scope>): <summary>`.

- `type`: `feat`, `fix`, `refactor`, `style`, `perf`, `docs`, `test`, `build`, `chore`, `ci`
- `scope` — опционально, имя компонента/области в нижнем регистре: `button`, `header`, `hero`, `tokens`, `deps`
- `summary` — на английском, в нижнем регистре, в повелительном наклонении, без точки в конце, до 72 символов
- Тело — опционально, через пустую строку; список изменений через `- `, тоже на английском
- Ломающие изменения: `!` после scope (`refactor(button)!: ...`) и/или секция `BREAKING CHANGE:` в теле
- Один коммит — одна логическая задача; если в диффе несколько несвязанных тем, предложить разбить его

# Компоненты

Раскладка и правила — в `components/README.md`. Коротко: `ui/` (примитивы),
`typography/`, `icons/` (чистые SVG), `layout/`, `social/`, доменные папки
(`menu/`). Импорт всегда абсолютный: `@/components/<категория>/<Имя>`.
Barrel-файлы не используем.
Обёртка секции (ширина, поля, 12 колонок) — `components/layout/Section.tsx`;
классы сетки руками не дублируем.
