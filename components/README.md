# Структура компонентов

Папка — это ответ на вопрос «что это за компонент», а не «на какой он странице».
Импорт всегда абсолютный: `@/components/<категория>/<Имя>`.

| Категория     | Что кладём                                                            | Сейчас                                        |
| ------------- | --------------------------------------------------------------------- | --------------------------------------------- |
| `ui/`         | Переиспользуемые примитивы без знания о домене: кнопки, ссылки, декор | `Button`, `NavLink`, `TerracottaPattern`      |
| `typography/` | Текстовые компоненты: заголовки, абзацы                               | `H1Title`, `H2Title`, `H3Title`, `Paragraph`  |
| `icons/`      | Чистые SVG без логики: только `size` / `className` / `currentColor`   | `Acorn`, `Arrow`, `Chevron`, `Pepper`, `Logo` |
| `layout/`     | Каркас страницы и layout-примитивы: сетка, шапка, подвал              | `Section`, `Header`, `Footer`                 |
| `menu/`       | Домен «меню»: знает про блюда, теги, цены                             | `MenuCard`, `DishTag`                         |
| `social/`     | Ссылки на мессенджеры с фирменными цветами                            | `Telegram`, `WhatsApp`, `Max`                 |

## Сетка

Ширина полосы контента, боковые поля и 12-колоночная сетка живут в одном месте —
`layout/Section.tsx`. Руками `mx-auto grid max-w-480 grid-cols-12 gap-6 px-60`
больше не пишем.

```tsx
<Section className="pt-12 pb-30">
  <div className="col-span-6">…</div>
  <div className="col-span-6">…</div>
</Section>
```

- Вертикальные отступы задаёт вызывающий через `className` — они у каждой секции свои.
- `grid={false}` — только контейнер без сетки, для блоков на flex (шапка).
- `as` меняет тег: `section` (по умолчанию), `header`, `footer`, `div`, `nav`.
- Ширину колонок задаём через `col-span-*` на детях, а не вложенной второй сеткой.

## Правила

- **Один компонент — один файл**, имя файла = имя компонента в `PascalCase`.
- **Направление зависимостей — вниз по списку.** `ui/`, `typography/` и `icons/`
  ничего не знают о `menu/`, `layout/` и `social/`. Доменные и лейаут-компоненты
  свободно тянут примитивы. Обратный импорт — сигнал, что примитив пора выносить.
- **Иконки не содержат интерактива.** Как только у SVG появляется `href`,
  `onClick` или состояние — это компонент `ui/` или домена, который _использует_ иконку.
- **Домен растёт папками.** Новый раздел (например, бронирование) — новая папка
  `components/booking/`, а не файлы в `ui/`.
- **Barrel-файлов (`index.ts`) нет намеренно** — они удлиняют сборку Next.js
  и ломают гранулярность tree-shaking. Импортируем файл напрямую.
- Общие типы компонента живут рядом с ним и экспортируются именованно
  (`export type DishTagId` в `menu/DishTag.tsx`).

## Где что ещё лежит

- `lib/` — утилиты без JSX (`cn`).
- `app/` — только роуты и композиция страниц; вёрстку выносим в компоненты.
- `app/tokens.css` — дизайн-токены, `app/globals.css` — базовые стили.
